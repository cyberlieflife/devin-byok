# Devin BYOK 适配 Devin/Windsurf 3.7.16 完整文档

> 日期：2026-08-13
> 目标版本：Devin（Windsurf）3.7.16 / productVersion 1.126.0
> 状态：核心链路已验证可用（登录 + 模型列表），聊天链路待最终确认；环境自动化尚未写进代码

---

## 1. 背景

devin-byok 是让 Devin（原 Windsurf）使用自有模型服务（BYOK）的工具。v1.2.9 基于旧版 Devin 协议（`exa.api_server_pb.ApiServerService`）工作，通过拦截 language_server 的 `--api_server_url` 参数 + 伪造 GetUserStatus/GetUserJwt/GetModelStatuses 等 RPC 响应实现纯本地模型路由。

Devin 升级到 3.7.16 后 v1.2.9 失效，表现为：

- 模型选择器里没有 BYOK 模型
- 无法发送消息
- 扩展日志：`user not logged in yet`、`metadata.api_key ... must be at least 1 characters`

---

## 2. 失效根因（诊断结论）

1. **language_server 直连官方**：新版 LS 除 `--api_server_url` 外，还有一路硬编码/多租户模式的官方连接（`server.codeium.com` / `api.codeium.com`，实测 `35.223.238.178:443`），模型/鉴权/聊天请求全部走了官方，本地 API 只收到 Ping + 埋点。
2. **协议换代**：RPC 服务从 `exa.api_server_pb.ApiServerService` 迁移到 `exa.language_server_pb.LanguageServerService`（100+ 方法）、`exa.seat_management_pb.SeatManagementService`、`exa.auth_pb.AuthService`、`exa.cascade_plugins_pb.CascadePluginsService` 等。
3. **鉴权换代**：从 JWT 换成 Windsurf API Key（`sk-ws-01-...`）+ `metadata.api_key` 校验；登录走 `SeatManagementService/RegisterUser`。
4. **`--portal_url` 只在多租户模式下由扩展传入**，单租户模式 LS 使用默认官方 portal。
5. **Devin.app 包被系统保护**：macOS 26 上签名应用包（hardened runtime）自某时刻起拒绝外部进程写入（`Operation not permitted`），旧方案的「替换 bundle 内 language_server」路径无法再用于部署。
6. **原生 BYOK 已内置**：3.7.16 自带 `API_PROVIDER_ANTHROPIC_BYOK` / `OPENAI_COMPATIBLE_EXTERNAL` / `OPEN_ROUTER_BYOK` 等枚举，但配置是**服务端团队级**（`TEAMS_FEATURES_API_KEY_ENABLED`），需要真实账号在网页端配置，纯本地不可用。

---

## 3. 已验证可用的适配方案

### 3.1 总链路

```
用户粘贴任意 token（假登录）
   │
   ▼
扩展 SeatManagementService/RegisterUser ──► 本地 API 8787（stub 返回伪造 Windsurf key）
   │
   ▼ 会话写入 secret storage（"windsurf_auth.sessions"）
扩展 _authenticateWithWindsurfApiKey（apiKey 经 parent pipe 发给 LS）
   │
   ▼
LS 向 API server（=本地 8787，被 wrapper 重写）发 GetUserStatus/GetUserJwt 校验
   │
   ▼ 本地 API 用旧格式 stub 应答（suffix 匹配兼容新服务名）
LS 标记已登录 → 扩展拉取模型
   │
   ▼
GetModelStatuses / GetCommandModelConfigs ──► 本地 API stub → BYOK 模型出现在选择器
   │
   ▼
聊天 GetChatMessage* ──► 本地 API → 转发用户配置的上游（OpenAI 兼容 / Anthropic）
```

### 3.2 关键机制一：`codeiumDev.languageServerBinaryPath` 覆盖启动 LS

Devin 扩展支持开发配置 `codeiumDev.*`，其中：

- `codeiumDev.languageServerBinaryPath`：指定 LS 二进制路径（覆盖 bundle 内置路径）。
- `codeiumDev.website`：portal 站点 URL（影响登录/profile 跳转，**不要指到本地**，会破坏登录页）。

**读取门槛**：`getConfig()` 对 `codeiumDev.*` 键只有在 `hasDevExtension()` 为真时才读真实值，否则返回默认值。而：

```js
hasDevExtension() = extensions.getExtension("Codeium.codeium-dev") !== undefined
```

所以需要**安装一个名为 `Codeium.codeium-dev` 的扩展壳**（只要 package.json 声明 publisher=Codeium、name=codeium-dev 即可，不需要代码）。安装后附加效果：

- 扩展启动 LS 时自动追加 `--dev_mode`
- `codeiumDev.*` settings 全部生效

当前机器实际状态：

```json
// ~/Library/Application Support/Devin/User/settings.json
{
  "codeium.apiServerUrl": "http://127.0.0.1:8787/_route/api_server",
  "codeium.inferenceApiServerUrl": "http://127.0.0.1:8787/_route/api_server",
  "codeiumDev.languageServerBinaryPath": "/Users/youniszhang/Library/Application Support/devin-byok/bin/devin-byok-ls-wrapper",
  "devin.portalUrl": "http://127.0.0.1:8787",
  "windsurf.portalUrl": "http://127.0.0.1:8787",
  "devin.multiTenantMode": true
}
```

- 扩展壳目录：`~/.devin/extensions/Codeium.codeium-dev-0.0.1/package.json`
- 注册表：`~/.devin/extensions/extensions.json`（含 `Codeium.codeium-dev` 条目）
- wrapper 真实 LS 副本：`~/Library/Application Support/devin-byok/bin/language_server_macos_arm.real`（从 Devin.app 拷贝）

### 3.3 关键机制二：wrapper 注入 `--portal_url` 等新参数

`cmd/ls-wrapper/main.go`（已修改）除重写 `--api_server_url` / `--inference_api_server_url` 外，新增：

| 注入参数 | 值 | 作用 |
|---|---|---|
| `--portal_url` | `http://127.0.0.1:8787` | 多租户模式下的 portal/API 基址 |
| `--register_user_url` | `http://127.0.0.1:8787/register_user/after` | 注册端点重定向 |

支持环境变量覆盖：`DEVIN_BYOK_API_SERVER_URL` / `DEVIN_BYOK_INFERENCE_API_SERVER_URL` / `DEVIN_BYOK_PORTAL_URL` / `DEVIN_BYOK_REGISTER_USER_URL`。

### 3.4 关键机制三：多租户模式

`devin.multiTenantMode: true` 使扩展在启动 LS 时追加：

```
--multitenant_mode --enterprise_mode [--portal_url <codeiumDev.website>]
```

多租户模式下 LS 以 `--portal_url` 作为 API 基址——这是让模型/鉴权请求全部回到本地的关键。wrapper 会无条件补 `--portal_url`（即使扩展没传）。

### 3.5 关键机制四：RegisterUser 假登录

- 登录框粘贴任意 token → 扩展调 `SeatManagementService/RegisterUser({firebase_id_token})`。
- 因为 `codeium.apiServerUrl` 指向本地，该请求打到本地 8787。
- 本地 stub（`internal/localapi/stubs.go` 新增 `buildRegisterUserResponse`）返回：

```proto
RegisterUserResponse {
  api_key = "sk-ws-01-byoklocal-fake-key-0000"   // field 1
  name    = "BYOK Local"                          // field 2
  api_server_url = "http://127.0.0.1:8787/_route/api_server"  // field 3
}
```

- 扩展把 apiKey 存进 secret storage（key = `windsurf_auth.sessions`），并 `persistSessionAndRestart` 重启 LS。
- 登录态持久化，机器上**只需假登录一次**。

### 3.6 关键机制五：旧 stub 的 suffix 匹配兼容新服务

本地 API 的 `serveRPC` 按方法名**后缀**路由，因此新服务名也能命中旧 stub：

| 新服务/方法 | 命中 stub |
|---|---|
| `exa.seat_management_pb.SeatManagementService/GetUserStatus` | `buildGetUserStatusResponse` |
| `exa.auth_pb.AuthService/GetUserJwt` | `buildGetUserJwtResponse` |
| `exa.api_server_pb.ApiServerService/GetModelStatuses` | `buildGetModelStatusesResponse` |
| `.../GetCommandModelConfigs` | `buildGetCommandModelConfigsResponse` |
| `.../CheckChatCapacity` / `CheckUserMessageRateLimit` | 对应 stub |

实测登录链路命中：`RegisterUser`×5、`GetUserStatus`×3、`GetUserJwt`×2、`GetProfileData`、`GetAllAcpRegistries`、`GetStatus`、`GetModelStatuses`、`GetCommandModelConfigs`。

## 4. 当前使用方式（本机已验证）

1. 启动 Devin BYOK GUI（本地 API 跑在 GUI 里，**需保持运行**；可开托盘自启）。
2. 打开 Devin。
3. 若未登录：登录框粘贴任意 token（假登录，几秒）。
4. 模型选择器出现 BYOK 模型，正常聊天。

## 7. 风险与注意

1. **Devin.app 的旧 wrapper 无法还原**（bundle 写入被系统禁止）：目前由 `languageServerBinaryPath` 覆盖绕过，settings 里的 `codeiumDev.languageServerBinaryPath` **必须保留**，否则 Devin 回退使用 bundle 内旧 wrapper（指向 8787，服务关闭即坏）。真实二进制仍完整保存在 `language_server_macos_arm.real`，若日后 bundle 保护解除可用 GUI 的 uninstall-wrapper 还原。
2. **`devin.multiTenantMode: true`** 可能让界面出现企业相关 UI，属正常。
3. **`codeiumDev.website` 不要指向本地**：它决定登录/profile 页跳转，曾导致浏览器下载空文件（本地 `/profile` 返回空）。
4. Devin 更新会升级 LS 二进制：wrapper 依赖 `.real` 副本，需在新版 Devin 后重新拷贝，工具应加版本检测。
5. 假登录返回固定 apiKey；若官方增加本地校验可能失效，届时需进一步伪造 `GetUserStatus`/`GetProfileData` 的新格式响应。
